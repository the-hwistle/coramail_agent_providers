# DECISION-001 PostgreSQL을 원본 업무 데이터 저장소로 사용

## 상태

채택

---

## 맥락

CoRA Mail Agent는 이메일 원문, 수신자, 첨부파일, 업무 분류, 담당자 라우팅, 사용자 수정, 처리 작업, 감사 로그를 저장해야 한다.

이 데이터는 서로 관계가 많고, 중복 전달과 누락 방지를 위해 상태 변경 이력과 현재 상태를 함께 관리해야 한다. AI 분석 결과도 원본 메일과 분리해 저장해야 하며, 프롬프트 버전, 모델, 신뢰도, 검증 결과 같은 구조화된 메타데이터를 함께 남겨야 한다.

---

## 결정

PostgreSQL을 원본 업무 데이터 저장소로 사용한다.

Qdrant는 검색용 벡터 저장소로 사용하고, 원본 업무 데이터의 최종 기준은 PostgreSQL에 둔다.

---

## 근거

- 이메일, 수신자, 첨부파일, 분석 결과, 담당자, 이력 데이터는 관계형 모델로 표현하기 적합하다.
- 중복 전달과 누락 방지를 위해 트랜잭션, 유일성 제약, 외래 키, 상태 이력이 필요하다.
- AI 결과는 구조가 변할 수 있으므로 일부 필드에는 JSONB가 필요하다.
- PostgreSQL은 JSONB 저장과 인덱싱을 지원한다.
- PostgreSQL은 전문 검색 기능을 제공하므로 초기에는 제목, 본문, 발신자 기반의 키워드 검색도 함께 구현할 수 있다.
- 운영 단계에서 감사 로그, 처리 작업, 사용자 수정 이력을 SQL로 분석하기 쉽다.

---

## 대안

| 대안 | 판단 |
|---|---|
| SQLite | 데모와 로컬 실험에는 유용하다. 동시 작업, 운영 이력, 확장성 기준에서는 PostgreSQL을 우선한다. |
| MongoDB | 유동적인 문서 저장에는 강점이 있지만 이메일, 담당자, 라우팅, 이력 관계를 엄밀하게 관리하기에는 PostgreSQL이 더 적합하다. |
| Qdrant 단독 저장 | 벡터 검색에는 적합하지만 원본 업무 데이터, 트랜잭션, 감사 이력의 기준 저장소로 사용하기 어렵다. |

---

## 영향

- SQLAlchemy 모델과 Alembic 마이그레이션을 작성한다.
- 이메일 원문과 AI 결과를 분리한 테이블 구조를 유지한다.
- JSONB는 구조가 자주 바뀌는 AI 출력 보조 데이터에 제한적으로 사용한다.
- 검색 인덱스와 원본 데이터 연결을 위해 Qdrant point와 PostgreSQL row의 매핑 테이블을 둔다.

---

## 변경 판단 기준

- 실제 운영에서 PostgreSQL 단일 인스턴스로 처리하기 어려운 처리량이 확인된다.
- 고객이 이미 다른 업무 DB를 표준으로 사용하고 직접 연동을 요구한다.
- 이메일 원본 저장 정책이 별도 문서 저장소 중심으로 바뀐다.
