# CoRA Mail 사용자 유형

## 문서 목적

이 문서는 CoRA Mail을 사용하는 사람과 운영하는 사람의 역할, 목표, 책임 범위를 정의한다.

사용자 유형은 화면 권한을 나누기 위한 기준에만 머물지 않는다. 각 사용자가 어떤 결과를 기대하는지, AI 판단이 잘못되었을 때 누가 수정하는지, 어떤 성능 지표가 실제 업무 품질과 연결되는지를 결정하는 기준으로 사용한다.

## 사용자 유형 구분 원칙

CoRA Mail의 사용자 유형은 직급이나 조직명이 아니라 **서비스에서 수행하는 책임**을 기준으로 구분한다.

한 사람이 여러 사용자 유형에 해당할 수 있다. 예를 들어 소규모 조직에서는 업무 관리자가 AI 운영 담당자의 역할을 함께 수행할 수 있다.

---

## UT-01 업무 담당자

### 정의

영업, 구매, 기술, 서비스 등 특정 업무 영역의 메일을 확인하고 실제 후속 업무를 수행하는 사용자다.

### 주요 목표

- 자신이 확인해야 할 메일을 빠르게 찾는다.
- 메일 전체를 읽기 전에 업무 유형과 핵심 요청을 파악한다.
- 첨부파일을 열기 전에 문서 유형과 주요 정보를 확인한다.
- 발주번호, 견적번호, 제품명, 수량, 선박명 등 업무 수행에 필요한 정보를 확인한다.
- 잘못된 AI 판단을 직접 수정한다.

### 주요 행동

- 받은편지함과 담당 메일 목록 조회
- 메일 상세 내용과 AI 분석 결과 확인
- 첨부파일 및 추출 정보 확인
- 업무 레이블 수정
- 긴급도 수정
- 담당자 변경
- 사람 검토 완료 표시
- 회신 또는 외부 업무 시스템에서 후속 조치 수행

### 기대하는 AI 결과

- 정확한 업무 분류
- 누락 없는 핵심 요청 요약
- 첨부파일의 문서 유형과 주요 정보
- 적절한 담당 대상
- 불확실한 판단에 대한 명확한 표시

### 주요 불편

- AI 분석이 끝날 때까지 화면이 멈춘다.
- 문의와 발주처럼 업무 경계가 가까운 메일을 잘못 구분한다.
- 첨부파일의 표에서 품목과 수량을 잘못 연결한다.
- 잘못된 담당자에게 메일이 전달된다.
- AI가 확신하지 못하면서도 확정적인 결과를 제시한다.

### 핵심 성과 지표

- 업무 레이블 사용자 수정률
- 담당자 변경률
- 핵심 정보 추출 정확도
- 메일 상세 화면 표시 시간
- 담당자 최초 확인 시간
- 사람 검토가 필요한 사례의 탐지율

## UT-02 업무 관리자

### 정의

전체 메일 흐름과 업무 배정 상태를 관리하고, 누락되거나 지연된 업무가 없는지 확인하는 사용자다.

### 주요 목표

- 긴급 메일과 미확인 메일을 놓치지 않는다.
- 담당자가 지정되지 않은 메일을 찾는다.
- 특정 담당자에게 업무가 과도하게 몰리지 않도록 조정한다.
- AI가 반복해서 잘못 판단하는 업무 유형을 발견한다.
- 자동 분류와 배정이 실제 운영 기준에 맞는지 확인한다.

### 주요 행동

- 전체 메일 현황 조회
- 업무 유형별·긴급도별·담당자별 현황 확인
- 미배정 및 사람 검토 대기 메일 확인
- 담당자 재배정
- 잘못된 업무 레이블 수정
- 지연 업무 및 미확인 긴급 메일 확인
- AI 판단 오류 사례를 운영 담당자에게 전달

### 기대하는 AI 결과

- 긴급 업무의 높은 재현율
- 담당자 배정 근거와 후보 점수
- 사람 검토가 필요한 메일의 우선 표시
- 업무량과 처리 지연을 파악할 수 있는 상태 정보
- 실패한 분석과 재시도 상태의 명확한 구분

### 주요 불편

- 긴급 메일이 일반 메일 사이에 묻힌다.
- AI 분석 실패와 분석 대기 상태가 구분되지 않는다.
- 담당자 배정 이유를 확인할 수 없다.
- 전체 정확도는 높지만 중요한 발주나 클레임을 놓친다.
- 사용자 수정 기록이 남지 않아 동일한 오류가 반복된다.

### 핵심 성과 지표

- 긴급 메일 미탐지율
- 미배정 메일 수
- 사람 검토 대기 시간
- 담당자별 업무 편중도
- 분석 실패 상태로 남은 메일 수
- 중요 업무 유형별 재현율

## UT-03 AI 운영·개발 담당자

### 정의

메일 분류, 첨부파일 분석, 문맥 검색, 담당자 연결 등 AI 파이프라인의 성능과 안정성을 관찰하고 개선하는 사용자다.

### 주요 목표

- 어느 단계에서 오류와 지연이 발생하는지 확인한다.
- 프롬프트, 모델, 검색 설정, 업무 규칙의 변경 효과를 비교한다.
- 사용자 수정과 실패 사례를 평가 데이터로 축적한다.
- 정확도, 지연 시간, 비용을 함께 관리한다.
- 운영 중인 모델과 프롬프트 버전을 재현할 수 있도록 기록한다.

### 주요 행동

- Trace, Span, Generation 기록 조회
- 업무 유형별 정확도와 재현율 분석
- 지연 시간의 P50, P95, P99 확인
- 실패 원인 및 재시도 결과 분석
- 프롬프트·모델·검색 설정별 실험
- 사용자 수정 사례 검토
- 평가 데이터셋 구성 및 회귀 평가
- 운영 버전 승격 또는 이전 버전 복구

### 기대하는 시스템 정보

- 메일 단위 전체 Trace
- 수집, 전처리, 첨부파일 분석, 검색, LLM 호출, 후처리 단계별 Span
- 프롬프트 이름과 버전
- 모델 이름과 생성 설정
- 입력·출력 토큰 수
- 검색 문서와 유사도 점수
- 최초 AI 결과와 사용자 수정 결과
- 오류 유형, 재시도 횟수, 최종 상태

### 주요 불편

- 전체 처리 시간만 있고 단계별 시간이 없다.
- 프롬프트나 모델 버전이 기록되지 않아 결과를 재현할 수 없다.
- 사용자 수정 결과와 최초 AI 출력이 연결되지 않는다.
- 정확도는 개선되었지만 지연 시간이나 비용이 급증한다.
- 특정 업무 유형을 개선한 뒤 다른 유형의 성능이 악화된다.

### 핵심 성과 지표

- 업무 유형별 정확도·정밀도·재현율
- 첨부 문서 유형별 추출 정확도
- 단계별 P50·P95·P99 지연 시간
- LLM 호출당 토큰 수와 비용
- JSON 구조 검증 실패율
- 재시도율과 재시도 성공률
- 사용자 수정률
- 평가 데이터 회귀 통과율

## 향후 분리 기준

현재는 사용자 유형이 세 가지이므로 한 파일에서 관리한다.

다음 조건 중 하나가 충족되면 `UT-01.md`, `UT-02.md`와 같이 파일을 분리한다.

- 사용자 유형이 다섯 개 이상으로 늘어난다.
- 유형별 권한과 화면 요구 사항이 별도 문서 수준으로 커진다.
- 사용자 조사 결과, 업무 흐름, 인터뷰 기록을 유형별로 관리해야 한다.
- 사용자 유형별 인수 조건과 평가 지표가 크게 달라진다.
