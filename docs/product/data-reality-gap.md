# 데이터 현실 차이

## 문서 목적

이 문서는 현재 제공받은 데이터와 실제 서비스 환경에서 처리해야 할 데이터의 차이를 정의한다.

CoRA Mail Agent의 초기 개발은 시연 가능한 데모를 우선한다. 데모의 신뢰도를 확보하려면 현재 데이터로 검증할 수 있는 범위와 추가 데이터가 필요한 범위를 구분해야 한다.

이 문서는 다음 판단의 기준으로 사용한다.

- 데모용 샘플 데이터 구성
- AI 분석 결과의 신뢰도 해석
- 초기 평가 데이터 범위 결정
- 고객에게 추가 요청할 데이터 정의
- 운영 전 검증해야 할 항목 정리
- Knowledge Graph와 Assignment Context Retrieval 가설의 검증 범위 판단

Knowledge Graph, GraphRAG, 미래 Search Agent 관련 데이터 해석 기준은 [Knowledge Graph Context And Search Agent](../architecture/knowledge-graph-context-and-search-agent.md)와 함께 적용한다.

## 실제 서비스 환경

실제 서비스 환경에서는 플루맥스의 공유 Gmail 계정으로 하루 약 400~600건의 비즈니스 메일이 유입된다.

현재 업무 처리 방식은 다음과 같다.

1. 5명의 직원이 하나의 Gmail 계정에 함께 접속한다.
2. 각 직원이 메일을 직접 확인한다.
3. 메일을 발주, 문의, 서비스, 기술, 기타 등으로 분류한다.
4. 각 업무 영역에 맞는 담당자에게 메일을 전달한다.
5. 담당자는 전달받은 메일을 확인하고 후속 업무를 수행한다.

실제 서비스에서 시스템이 처리해야 할 데이터는 다음과 같다.

| 데이터 유형 | 설명 |
|---|---|
| 수신 메일 | 고객, 협력사, 선사, 대리점 등 외부에서 공유 Gmail 계정으로 보낸 메일 |
| 답장 메일 | 기존 대화의 연장선에서 들어오는 짧은 응답 또는 확인 메일 |
| 첨부파일 포함 메일 | 견적 요청서, 발주서, 사양서, 도면, 사진, 서비스 문서가 포함된 메일 |
| 긴급 요청 메일 | 납기, 클레임, 서비스, 선박 운항 일정과 관련된 긴급성이 있는 메일 |
| 업무 경계 사례 | 문의와 발주, 기술 검토와 서비스 요청처럼 분류가 애매한 메일 |
| 중복 가능 메일 | 여러 직원이 같은 담당자에게 전달할 수 있는 메일 |
| 누락 가능 메일 | 담당자에게 전달되지 않고 공유 계정에 남을 수 있는 메일 |

## 현재 제공 데이터

현재 제공받은 데이터는 주로 플루맥스가 발신한 메일이다.

이 데이터는 플루맥스의 실제 업무 표현, 제품명, 첨부파일 형식, 답변 방식, 고객 응대 패턴을 파악하는 데 사용할 수 있다.

| 항목 | 현재 상태 |
|---|---|
| 데이터 출처 | 플루맥스 발신 메일 중심 |
| 업무 방향 | 내부 또는 플루맥스 측 발신 응답 중심 |
| 수신 문의 데이터 | 추가 확보 필요 |
| 실제 분류 전 원본 메일 | 추가 확보 필요 |
| 담당자 전달 이력 | 추가 확보 필요 |
| 중복 전달 사례 | 추가 확보 필요 |
| 누락 사례 | 추가 확보 필요 |
| 첨부파일 원본 | 보유 범위 확인 필요 |

---

## 데이터 차이

현재 데이터와 실제 서비스 데이터는 메일 방향, 업무 상태, 판단 대상이 다르다.

| 구분 | 현재 제공 데이터 | 실제 서비스 목표 데이터 |
|---|---|---|
| 메일 방향 | 플루맥스 발신 메일 중심 | 공유 Gmail 계정 수신 메일 중심 |
| 업무 상태 | 사람이 이미 판단하고 응답한 뒤의 결과가 많음 | 시스템이 처음 판단해야 하는 원본 요청 |
| 분류 정보 | 명시적으로 남아 있지 않을 수 있음 | 발주, 문의, 서비스, 기술, 기타 분류 필요 |
| 담당자 정보 | 실제 전달 대상과 판단 근거 확인 필요 | 담당자 또는 `assignee_area` 자동 제안 필요 |
| 중복/누락 여부 | 직접 관찰하기 어려움 | 운영 문제의 핵심 검증 대상 |
| 첨부파일 의미 | 응답 과정의 첨부파일일 수 있음 | 요청 이해를 위한 입력 첨부파일 |
| 평가 활용 | 표현과 양식 참고에 적합 | 성능 평가와 운영 검증에 필요 |

---

## 현재 데이터로 검증 가능한 항목

현재 제공 데이터로 다음 항목을 제한적으로 검증할 수 있다.

- 플루맥스 업무 메일에서 자주 사용되는 표현
- 제품명, 부품명, 선박 관련 용어
- 고객 응대 문장과 답변 톤
- 첨부파일 이름과 형식 패턴
- 견적, 발주, 기술, 서비스 관련 업무 용어
- 이메일 답변 초안 생성의 스타일 참고
- 샘플 수신 메일을 만들기 위한 업무 맥락 추출

---

## 현재 데이터로 검증이 어려운 항목

현재 제공 데이터만으로 다음 항목의 실제 성능을 판단하기 어렵다.

- 공유 Gmail 계정에 유입되는 실제 수신 메일 분류 정확도
- 하루 400~600건 처리 환경에서의 우선순위 판단 품질
- 실제 담당자 라우팅 정확도
- 중복 전달 감소 효과
- 담당자 전달 누락 감소 효과
- 고객이 보낸 원본 첨부파일 이해 정확도
- 업무 경계 사례의 분류 품질
- 실제 운영 환경의 실패 유형과 재시도 필요성

이 항목들은 샘플 데이터로 데모 흐름을 확인한 뒤, 실제 수신 데이터 확보 시 별도 평가가 필요하다.

## 샘플 데이터 재구성 원칙

데모용 샘플 데이터는 현재 제공 데이터를 참고하되, 실제 서비스에서 처리해야 할 수신 메일 형태로 재구성한다.

샘플 데이터는 다음 원칙을 따른다.

- 샘플마다 출처와 생성 방식을 기록한다.
- 실제 발신 메일에서 추출한 업무 표현과 제품 용어를 사용한다.
- 고객이 공유 Gmail 계정으로 보낸 수신 메일 형태로 작성한다.
- 업무 유형별 최소 대표 사례를 포함한다.
- 첨부파일 중심 메일과 본문 중심 메일을 함께 포함한다.
- 중요도 높은 메일과 일반 메일을 함께 포함한다.
- 담당자 판단이 명확한 사례와 애매한 사례를 함께 포함한다.
- 샘플 데이터 기반 결과를 운영 성능으로 표현하지 않는다.

---

## 최소 샘플 유형

초기 데모에는 다음 샘플 유형을 포함한다.

| ID | 샘플 유형 | 목적 |
|---|---|---|
| SD-01 | 신규 문의 메일 | 이메일 의도 분석과 핵심 정보 추출 확인 |
| SD-02 | 견적 요청 메일 | 문의 분류와 견적 업무 판단 확인 |
| SD-03 | 발주 요청 메일 | 발주 분류와 `assignee_area` 제안 확인 |
| SD-04 | 서비스 요청 메일 | 서비스 분류와 중요도 산정 확인 |
| SD-05 | 기술 검토 요청 메일 | 기술 업무 분류와 첨부파일 이해 확인 |
| SD-06 | 기타 메일 | 업무 외 또는 낮은 우선순위 메일 처리 확인 |
| SD-07 | 긴급 요청 메일 | 중요도 산정과 우선 표시 확인 |
| SD-08 | 짧은 본문과 첨부파일 중심 메일 | 첨부파일 분석 의존 흐름 확인 |
| SD-09 | 담당자 판단이 애매한 메일 | 사람 검토 전환 확인 |
| SD-10 | 중복 가능 메일 | 중복 전달 방지 흐름 확인 |
| SD-11 | 누락 가능 메일 | 미처리 또는 미배정 상태 표시 확인 |

## 고객에게 추가 요청할 데이터

운영 검증을 위해 다음 데이터가 필요하다.

| 데이터 | 필요 이유 |
|---|---|
| 실제 공유 Gmail 수신 메일 샘플 | 의도 분석, 업무 분류, 중요도 산정 검증 |
| 첨부파일 포함 수신 메일 | 첨부파일 이해와 핵심 정보 추출 검증 |
| 담당자 전달 이력 | 라우팅 기준과 정답 데이터 구성 |
| 중복 전달 사례 | 중복 방지 기능 검증 |
| 누락 또는 지연 처리 사례 | 누락 방지와 미처리 상태 관리 검증 |
| 업무 유형별 담당자 기준 | `assignee_area` 제안 규칙 정의 |
| 중요도 판단 기준 | 긴급 메일 우선순위 기준 정의 |
| 실제 답변 메일 | 답변 초안 생성 톤과 형식 정의 |

개인정보, 영업상 민감 정보, 고객 식별 정보는 마스킹하거나 별도 보안 기준에 따라 처리한다.

## 데모 결과 해석 기준

데모 결과는 다음 범위에서 해석한다.

- 화면 흐름이 실제 업무 처리 과정을 설명할 수 있는지 확인한다.
- Agent 출력 스키마가 안정적으로 생성되는지 확인한다.
- 업무 유형, 중요도, 핵심 정보, `assignee_area`가 화면에 표시되는지 확인한다.
- 실패 상태와 사람 검토 상태가 표시되는지 확인한다.
- 샘플 데이터에 대한 결과를 운영 성능 지표로 사용하지 않는다.

운영 성능은 실제 공유 Gmail 수신 메일과 담당자 처리 이력을 확보한 뒤 별도 평가한다.
