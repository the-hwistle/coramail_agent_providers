# SC-08 대량 메일 유입 시 우선순위 처리

## 목적

업무 시작 시간이나 시스템 재연결 이후 많은 메일이 한꺼번에 유입되어도 시스템이 중단되지 않고, 긴급하거나 중요한 메일부터 분석하도록 한다.

## 주요 사용자

- 업무 관리자
- AI 운영·개발 담당자
- 업무 담당자

## 상황

메일함 재연결, 장시간 동기화 중단 또는 업무 시작 시간대에 수십 건에서 수백 건의 신규·변경 메일이 동시에 발견된다.

## 사전 조건

- 메일 저장과 AI 분석 작업이 분리되어 있다.
- 분석 작업을 대기열에서 관리할 수 있다.
- 동시 실행 수와 재시도 횟수를 제한할 수 있다.
- 메일별 진행 상태를 저장할 수 있다.

## 시작 조건

한 번의 동기화 주기에서 대량의 신규 또는 변경 메일이 발견된다.

## 정상 흐름

1. 시스템이 모든 신규·변경 메일의 원문과 메타데이터를 먼저 저장한다.
2. 각 메일에 분석 작업을 생성한다.
3. 첨부파일 유무, 최근성, 발신자, 긴급 키워드 등으로 초기 우선순위를 계산한다.
4. 긴급 가능성이 높은 메일을 우선 대기열에 배치한다.
5. LLM과 첨부파일 분석의 동시 실행 수를 제한한다.
6. 서로 독립적인 전처리와 첨부파일 분석은 가능한 범위에서 병렬 실행한다.
7. 메일별 진행 상태와 대기 시간을 기록한다.
8. 일부 작업이 실패해도 나머지 작업은 계속 실행한다.
9. 완료된 메일부터 받은편지함에 AI 결과를 표시한다.
10. 관리자는 대기 작업 수, 실패 작업 수, 긴급 메일 처리 상태를 확인한다.

## 예외 흐름

- 모델 서버가 과부하 상태면 신규 호출을 늦추고 대기열을 유지한다.
- 큰 첨부파일은 별도의 낮은 동시 실행 제한을 적용한다.
- 긴급 후보의 분석이 실패하면 사람 검토 대상으로 즉시 표시한다.
- 대기 시간이 기준값을 넘으면 관리자 경고 상태로 전환한다.

## 기대 결과

- 메일 원문은 유입 순서와 무관하게 모두 저장된다.
- 긴급 가능성이 높은 메일은 일반 메일보다 먼저 분석된다.
- 시스템 부하가 설정된 한도를 넘지 않는다.
- 일부 실패가 전체 일괄 작업 실패로 이어지지 않는다.
- 사용자는 완료된 메일부터 확인할 수 있다.

## 사람 검토 조건

- 긴급 후보가 분석 제한 시간을 넘었다.
- 대기 시간이 운영 기준을 넘었다.
- 반복 재시도로 특정 작업이 대기열을 점유한다.
- 담당자를 찾지 못한 긴급 메일이 존재한다.

## 인수 기준

- 100건 동시 유입 시험에서 메일 원문 유실이 없다.
- 특정 메일 실패가 전체 처리 중단으로 이어지지 않는다.
- 긴급 후보의 처리 시작 시간이 일반 메일보다 빠르다.
- 대기열 길이, 대기 시간, 실행 시간을 각각 측정할 수 있다.
- 처리량 증가에 따른 P95 지연 시간 변화를 확인할 수 있다.
- LLM 동시 호출 수가 설정 한도를 넘지 않는다.

## LLMOps 및 시스템 관찰 항목

- 분당 수집 메일 수
- 분당 분석 완료 메일 수
- 대기열 길이
- 우선순위별 대기 시간
- 실행 시간과 전체 처리 시간
- 동시 실행 작업 수
- 첨부파일 유무별 처리 시간
- 파일 크기별 처리 시간
- P50·P95·P99 지연 시간
- LLM 서버 CPU·GPU·메모리 사용률
- 타임아웃 및 재시도 비율
- 시간당 입력·출력 토큰 수
- 시간당 추정 비용

## 평가 데이터 요구 사항

- 첨부파일 없는 간단한 메일
- PDF 첨부 메일
- 이미지 첨부 메일
- 긴급 서비스 요청
- 발주 확정 메일
- 분석 실패를 유발하는 파일
- 중복 메일
- 변경된 기존 메일
- 10건, 50건, 100건 단위 부하 묶음
