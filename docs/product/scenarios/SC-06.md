# SC-06 AI 오분류 수정 및 평가 데이터 축적

## 목적

사용자가 잘못된 AI 판단을 수정할 수 있도록 하고, 수정 기록을 재현 가능한 평가 데이터와 성능 개선 자료로 축적한다.

## 주요 사용자

- 업무 담당자
- 업무 관리자
- AI 운영·개발 담당자

## 상황

AI가 발주 메일을 문의로 분류하거나, 긴급도를 낮게 판단하거나, 잘못된 담당자를 추천한다.

## 사전 조건

- 사용자가 AI 분석 결과를 수정할 수 있다.
- 최초 AI 결과와 수정 결과를 별도로 저장할 수 있다.
- 실행 당시의 모델, 프롬프트, 검색 문맥을 기록할 수 있다.

## 시작 조건

사용자가 메일 상세 화면에서 AI 결과가 잘못되었음을 발견한다.

## 정상 흐름

1. 사용자가 최초 AI 분석 결과를 확인한다.
2. 업무 레이블, 긴급도, 추출 정보 또는 담당 대상을 수정한다.
3. 사용자가 가능한 경우 수정 사유를 선택하거나 입력한다.
4. 시스템은 최초 결과를 덮어쓰지 않고 수정 결과를 별도로 저장한다.
5. 실행 당시의 프롬프트 버전, 모델, 검색 문맥, 토큰 수, 단계별 시간을 연결한다.
6. 수정 사례를 평가 데이터 후보로 등록한다.
7. AI 운영 담당자가 사례의 정답 적합성을 검토한다.
8. 승인된 사례를 고정 평가 데이터셋에 추가한다.
9. 개선 버전을 동일 데이터셋으로 평가한다.
10. 기준을 통과한 변경만 운영 환경에 반영한다.

## 예외 흐름

- 여러 사용자가 서로 다른 수정을 하면 최종 확정 권한에 따라 정답을 결정한다.
- 수정 사유가 없더라도 최초 결과와 수정 결과는 반드시 저장한다.
- 개인정보 또는 민감한 첨부파일은 평가 데이터 반입 정책에 따라 비식별화한다.
- 단순 UI 오조작은 평가 데이터에서 제외할 수 있도록 표시한다.

## 기대 결과

- 최초 AI 결과와 사용자 확정 결과가 모두 보존된다.
- 어떤 모델과 프롬프트가 결과를 만들었는지 재현할 수 있다.
- 수정 사례가 평가 데이터 후보로 자동 연결된다.
- 개선 전후 성능을 동일한 기준으로 비교할 수 있다.

## 반드시 저장할 정보

- 메일 식별자와 스레드 식별자
- 최초 업무 레이블과 수정 업무 레이블
- 최초 긴급도와 수정 긴급도
- 최초 담당 대상과 수정 담당 대상
- 최초 추출 정보와 수정 추출 정보
- AI 신뢰도와 사람 검토 여부
- 검색에 사용한 문서와 점수
- 프롬프트 이름과 버전
- 모델 이름과 생성 설정
- 입력·출력 토큰 수
- 단계별 실행 시간
- 수정한 사용자와 수정 시각
- 수정 사유
- 평가 데이터 승인 상태

## 사람 검토 조건

이 시나리오 자체가 사람의 확정 결과를 수집하는 흐름이다. 다음 사례는 AI 운영 담당자가 추가 검토한다.

- 사용자 간 수정 결과가 충돌한다.
- 정답 기준이 업무 정책상 불명확하다.
- 여러 업무 유형이 동시에 포함되어 단일 레이블로 표현하기 어렵다.
- 개인정보 또는 민감 정보가 포함되어 있다.

## 인수 기준

- 모든 사용자 수정이 최초 결과와 함께 저장된다.
- 수정 사례의 95% 이상에서 모델·프롬프트 버전을 확인할 수 있다.
- 승인된 평가 사례를 동일 입력으로 재실행할 수 있다.
- 개선 버전 평가 시 기존 주요 시나리오의 성능 저하를 탐지한다.
- 사용자 수정 저장 시간이 P95 1초 이내다.

- 업무 유형별 수정률

- 수정 사유 분포
- 사람 검토 필요 예측의 적중률
- 동일 오류의 반복 빈도
- 평가 데이터셋 버전
- 개선 전후 정확도·지연 시간·비용 변화

## 평가 데이터 요구 사항

사용자 수정 사례 자체가 평가 데이터 후보가 된다. 다음 기준으로 균형을 맞춘다.

- 업무 유형별 충분한 사례 수
- 첨부파일 유무
- 한글 및 영문
- 명확한 사례와 경계 사례
- 정상 성공과 분석 실패
- 긴급 및 비긴급
- 단일 요청과 복합 요청
