# SC-05 클레임 및 긴급 서비스 요청 탐지

## 목적

하자, 고장, 파손, 수리 요청을 서비스 업무로 분류하고 업무 중단 가능성이 높은 메일을 우선 노출한다.

## 주요 사용자

- 업무 담당자
- 업무 관리자

## 상황

고객이 납품 제품의 고장, 파손, 작동 불량 또는 긴급 수리를 요청한다. 생산 중단, 운항 차질, 즉시 대응과 같은 표현이 포함될 수 있다.

## 사전 조건

- 서비스 업무와 긴급도 판단 기준이 정의되어 있다.
- 메일 목록에서 긴급 상태를 우선 표시할 수 있다.
- 담당자 확인 상태를 기록할 수 있다.

## 시작 조건

클레임, 고장 또는 수리 관련 표현이 포함된 신규 메일이 발견된다.

## 정상 흐름

1. 시스템이 메일과 첨부파일을 수집한다.
2. 하자, 고장, 파손, 수리, A/S 관련 표현을 탐지한다.
3. 메일을 `서비스`로 분류한다.
4. 생산 중단, 운항 차질, 안전 문제, 즉시 대응 요청을 분석한다.
5. 긴급도를 결정한다.
6. 제품명, 납품번호, 증상, 발생 시점, 요청 행동을 추출한다.
7. 서비스 담당자를 계산한다.
8. 긴급 메일을 목록 상단과 관리자 현황에 표시한다.
9. 담당자가 메일을 확인하면 최초 확인 시각을 기록한다.

## 예외 흐름

- 불만 표현만 있고 실제 하자나 수리 요청이 없으면 일반 문의 또는 기타로 분류한다.
- 긴급 표현은 있지만 업무 영향이 불명확하면 사람 검토 대상으로 보낸다.
- 안전 관련 표현이 있으면 낮은 신뢰도라도 긴급 후보로 표시한다.
- 담당자를 찾지 못하면 미배정 긴급 메일로 관리자에게 표시한다.

## 기대 결과

- 업무 레이블: 서비스
- 긴급도: 일반, 높음 또는 긴급
- 핵심 정보: 제품명, 납품번호, 증상, 발생 시점, 요청 대응
- 담당 대상: 서비스 또는 기술 지원 담당자
- 긴급 상태와 판단 근거

## 사람 검토 조건

- 긴급도 판단 신뢰도가 낮다.
- 안전 관련 표현이 탐지되었다.
- 서비스와 일반 문의의 경계가 불명확하다.
- 제품 또는 납품 정보를 찾지 못했다.
- 담당자를 결정하지 못했다.

## 인수 기준

- 서비스 메일 재현율 95% 이상
- 긴급 메일 재현율 95% 이상
- 긴급도 과대 판단 비율 10% 이하
- 긴급 메일이 수집된 후 1분 이내 목록에 표시된다.
- 미배정 긴급 메일이 관리자 화면에서 누락되지 않는다.

- 긴급도 후보 점수와 판단 근거

- 수집부터 긴급 표시까지 걸린 시간
- 담당자 최초 확인 시간
- 업무 시간대·비업무 시간대별 지연
- 미배정 상태 지속 시간
- 사용자 긴급도 수정 결과

## 평가 데이터 요구 사항

- 일반 수리 요청
- 생산 중단을 동반한 고장
- 운항 차질을 동반한 고장
- 안전 위험 표현이 포함된 사례
- 강한 불만이지만 긴급하지 않은 사례
- 단순 사용법 문의
- 제품·납품번호가 누락된 사례
