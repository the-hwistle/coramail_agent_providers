# SC-02 견적의뢰서 첨부 메일 분석

## 목적

메일 본문보다 첨부 문서에 핵심 정보가 담긴 견적 요청을 분석하고, 사용자가 원본 파일을 열기 전에 업무에 필요한 정보를 확인하도록 돕는다.

## 주요 사용자

- 업무 담당자
- 업무 관리자

## 상황

고객이 RFQ 또는 견적의뢰서 PDF를 첨부하여 견적을 요청한다. 본문에는 “첨부파일을 확인해 달라”는 짧은 문장만 있을 수 있다.

## 사전 조건

- 첨부파일 다운로드가 가능하다.
- PDF 또는 이미지의 텍스트와 구조를 분석할 수 있다.
- 첨부 문서 유형 정의가 등록되어 있다.
- 메일 본문과 첨부파일 분석 결과를 함께 판단할 수 있다.

## 시작 조건

첨부파일이 포함된 신규 수신 메일이 발견된다.

## 정상 흐름

1. 시스템이 메일과 첨부파일 메타데이터를 수집한다.
2. 원본 메일을 저장한다.
3. 첨부파일의 형식, 크기, 페이지 수를 확인한다.
4. 첨부파일에서 텍스트와 구조 정보를 추출한다.
5. AI가 첨부 문서를 견적의뢰서로 분류한다.
6. 참조번호, 선박명, 프로젝트명, 품목, 수량, 요청 납기 등을 추출한다.
7. 메일 본문과 첨부파일 분석 결과를 결합한다.
8. 메일을 `문의`로 분류하고 요청 행동을 `견적 작성 및 회신`으로 판단한다.
9. 적절한 담당 대상을 계산한다.
10. 추출 결과와 원본 근거 위치를 저장한다.
11. 사용자가 메일 상세 화면에서 분석 결과를 확인한다.

## 예외 흐름

- 텍스트 계층이 없는 PDF는 OCR 또는 이미지 분석 경로로 전환한다.
- 암호화되었거나 손상된 파일은 분석 불가 상태로 표시한다.
- 표의 품목과 수량 연결이 불확실하면 행 단위 결과를 확정하지 않는다.
- 본문 판단과 첨부 문서 판단이 다르면 사람 검토 대상으로 보낸다.
- 파일 크기나 페이지 수가 제한을 넘으면 비동기 작업으로 분리한다.

## 기대 결과

- 업무 레이블: 문의
- 첨부 문서 유형: 견적의뢰서
- 요청 행동: 견적 작성 및 회신
- 핵심 정보: 참조번호, 선박명 또는 프로젝트명, 품목, 수량, 요청 납기
- 담당 대상: 영업 또는 견적 담당자

## 사람 검토 조건

- 문서 유형 신뢰도가 기준값보다 낮다.
- 핵심 참조번호를 찾지 못했다.
- 품목은 찾았지만 수량을 찾지 못했다.
- 여러 품목의 행 연결이 불확실하다.
- 본문과 첨부파일의 업무 판단이 서로 다르다.
- 첨부파일 분석이 실패했다.

## 인수 기준

- 견적의뢰서 분류 정확도 90% 이상
- 참조번호 추출 정확도 95% 이상
- 품목·수량 행 연결 정확도 90% 이상
- PDF 포함 메일의 전체 분석 시간 P95 45초 이내
- 분석 불가 파일이 사람 검토 대상으로 누락 없이 전환된다.
- 추출 결과에서 원본 근거를 확인할 수 있다.

- 파일 형식, 크기, 페이지 수
- 파일 다운로드 시간
- 텍스트 추출 시간
- OCR 또는 이미지 분석 시간
- 문서 유형과 신뢰도
- 필드별 추출 결과와 신뢰도
- 표 행 단위 추출 결과
- 첨부파일별 토큰 수
- 첨부파일별 처리 시간
- 실패 원인과 재시도 횟수

## 평가 데이터 요구 사항

- 텍스트 PDF
- 스캔 PDF
- 표가 한 페이지인 RFQ
- 여러 페이지에 걸친 RFQ
- 한글 및 영문 문서
- 품목명이 길거나 여러 줄인 문서
- 수량 단위가 다양한 문서
- 양식이 정해지지 않은 견적 요청
- 손상되거나 암호화된 실패 사례
