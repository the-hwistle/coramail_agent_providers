# CoRA Mail 비즈니스 준비 계획

기준일: 2026-09-22

## 목적

메일 연결과 화면 시연을 넘어, 고객 데이터를 안전하게 보존하고 장애를 복구하며 담당자 배정 품질을 반복 검증할 수 있는 상태를 비즈니스 준비 완료로 정의한다.

## 우선순위

| 우선순위 | 과제 | 완료 기준 | 현재 상태 |
|---|---|---|---|
| P0 | 공개 상태 정보 최소화 | 인증 전 상태 API는 서비스 상태만 반환한다. | 8040 배포 및 HTTP 검증 완료 |
| P0 | 브라우저 변경 요청 보호 | 다른 출처에서 보낸 변경 요청을 거부하고 모든 응답에 기본 보안 헤더를 적용한다. | 8040 배포 및 HTTP 검증 완료 |
| P0 | 원본 메일·첨부 백업 | PostgreSQL, Qdrant, 런타임 원본을 같은 백업 단위로 보존한다. | 구현됨 |
| P0 | 백업 산출물 자동 검증 | 불완전하거나 안전하지 않은 백업은 성공으로 보고하지 않는다. | 구현, 실제 백업 검증 및 배포 전 실행 완료 |
| P0 | 격리 복구 훈련 | 새 PostgreSQL/Qdrant/런타임 볼륨에 복구하고 메일·첨부·검색 경로를 확인한다. | 다음 운영 작업 |
| P0 | 고정 HTTPS와 비밀 관리 | 고정 도메인, TLS, 접근 정책, 외부 비밀 저장소를 운영한다. | 운영 환경 결정 필요 |
| P1 | 담당자 배정 품질 기준선 | 실제 또는 승인된 합성 평가셋으로 Top-1, Top-3, 자동 배정 precision을 측정한다. | 평가 데이터 필요 |
| P1 | 사용자 수정·감사 이력 | 최초 AI 결과와 사용자 확정·재배정·전달을 모두 보존한다. | 기능 점검 및 보강 필요 |

| P2 | 조직별 권한과 데이터 경계 | 역할 기반 권한, 조직별 데이터 분리, 감사 조회 권한을 적용한다. | 설계 필요 |
| P2 | 처리량 확장 | 웹 요청과 장시간 작업을 분리하고 worker 동시성, 제한, backpressure를 검증한다. | 부하 기준 필요 |
| P2 | 유지보수성 | 대형 UI/서버 모듈을 책임별로 분리하고 계약 테스트를 유지한다. | 단계적 수행 |

## 실행 순서

1. 인증 전 노출 정보, 교차 출처 변경 요청, 백업 검증을 P0 코드로 차단한다.
2. 현 운영 백업을 검증하고 별도 볼륨에서 정기 복구 훈련을 자동화한다.
3. 고정 HTTPS 주소와 비밀 저장 방식을 확정한 후 외부 접근 점검을 통과시킨다.
4. 확정 담당자와 근거가 포함된 평가셋을 구축하고 자동 배정은 precision 기준을 통과한 범위에만 적용한다.
5. 사용자 수정 이력과 공급자별 동기화 상태를 지표에 연결한다.
6. 실제 처리량과 조직 구조를 기준으로 worker, 권한, 데이터 경계를 확장한다.

## 출시 판정 기준

- P0 항목이 모두 완료되고 최근 격리 복구 훈련의 증거가 있어야 한다.
- Gmail, Naver, Hiworks의 동기화, 본문, 인라인 이미지, 첨부 원본 경로가 운영 환경에서 검증되어야 한다.
- 자동 담당자 배정은 승인된 평가셋의 목표 기준을 충족해야 하며, 미달하거나 근거가 부족한 경우 사람 검토로 전환되어야 한다.
- 장애, 부분 성공, 재시도, 사용자 수정이 감사 가능한 상태로 남아야 한다.
