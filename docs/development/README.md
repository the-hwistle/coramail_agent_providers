# CoRA Mail 개발 단계

## 문서 목적

이 문서는 Agentic RAG 기반 CoRA Mail Agent의 구현 순서와 완료 기준을 정의한다.

최종 목표는 메일 본문과 첨부파일을 함께 분석하고, 조직 규칙과 과거 확정 사례를 검색해 실제 업무 담당자를 근거와 함께 배정하는 것이다. 화면 데모, 요약, 분류는 이 목표를 검증하는 중간 단계이며 독립적인 완료 기준이 아니다.

목표 아키텍처와 상태 모델은 [Agentic RAG Mail Decision System](../architecture/agentic_rag_mail_decision_system.md)을 따른다.

## 개발 원칙

- 하나의 메일은 하나의 `Mail Decision Run`으로 분석한다.
- 첨부파일 분석, 사실 추출, 검색, 요약, 분류, 담당자 배정, 검증은 동일한 실행 상태와 근거를 공유한다.
- 로컬 텍스트 LLM, Vision LLM, 임베딩, reranker를 고객 내부 환경에서 실행할 수 있어야 한다.
- 임시 규칙 기반 결과를 완성된 AI 기능으로 간주하지 않는다.
- 운영 데이터가 부족하면 합성 담당자·고객·제품·프로젝트·메일·첨부·정답 데이터를 구축한다.
- 자동 배정 recall보다 precision을 우선하며 불확실한 사례는 사람 검토로 보낸다.
- 각 단계는 데이터 저장, API, 실행, 화면, 평가까지 연결되어야 완료된다.

## 단계 요약

| 단계 | 이름 | 목표 |
|---|---|---|
| M0 | 문서와 폐기 범위 확정 | 목표 구조, 기존 임시 구현의 폐기 범위, 데이터 계약을 고정한다. |
| M1 | Mail Decision 실행 기반 | 통합 실행 상태, 노드 실행 기록, 로컬 LLM Gateway, 구조화 출력 검증을 구현한다. |
| M2 | 첨부파일 이해 | PDF, 이미지, XLSX, DOCX를 분석하고 구조화 필드와 근거를 저장한다. |
| M3 | 통합 사실·요약·분류 | 본문과 첨부를 통합해 사실, 구조화 요약, 세부 업무 유형을 생성한다. |
| M4 | 조직·합성 데이터 기반 | 담당자 역량, 고객·제품·프로젝트 관계, 라우팅 규칙, 평가셋을 구축한다. |
| M5 | Agentic Retrieval | 정확 검색, 규칙 검색, Qdrant 검색, reranker, 검색 반복과 trace를 구현한다. |
| M6 | 담당자 배정 | 후보 계산, 검증, 자동 배정, 사람 검토, 재배정 이력을 구현한다. |
| M7 | 운영 평가와 안정화 | 품질·지연·실패·모델 버전·사용자 수정 평가를 운영 수준으로 강화한다. |
| M8 | 부가 기능 | 답변 초안, 견적 폼, 후속 행동 제안 등 2차 기능을 추가한다. |

## M0 문서와 폐기 범위 확정

### 주요 작업

- 목표 아키텍처와 `Mail Decision Run` 계약 확정
- 기존 규칙 기반 Worker, 문자열 요약, 독립 classification/summary job의 운영 폐기 결정
- 세부 업무 유형 taxonomy 확정
- 자동 배정과 사람 검토 정책 확정
- 신규 테이블과 기존 테이블의 역할 구분

### 완료 조건

- 관련 기능·아키텍처·의사결정 문서가 동일한 목표 구조를 설명한다.
- 임시 데모와 목표 구현의 경계가 명확하다.
- 상충하거나 중복된 준비 문서가 제거되거나 대체된다.

## M1 Mail Decision 실행 기반

### 주요 작업

- `mail_decision_runs`, `mail_decision_steps` 스키마와 repository 구현
- 결정적 Workflow Orchestrator 구현
- 로컬 OpenAI 호환 LLM Gateway 구현
- Pydantic 구조화 출력과 schema validation 구현
- 실행 재개, 중복 방지, retry, timeout, failure 상태 구현

### 완료 조건

- 메일 한 건의 실행 상태와 현재 노드를 조회할 수 있다.
- 노드별 모델, 프롬프트, 입력 hash, 지연, 오류가 기록된다.
- 실패 후 안전하게 재시작하거나 사람 검토로 전환할 수 있다.

## M2 첨부파일 이해

### 주요 작업

- PDF 텍스트·레이아웃 추출
- 스캔 PDF와 이미지 Vision LLM 분석
- XLSX 시트·표·셀 구조 분석
- DOCX 본문·표·삽입 이미지 분석
- 문서 유형, 필드, 표 행, 페이지·bbox 근거 저장
- `partial_success`, `failed`, `unsupported` 상태 구현

### 완료 조건

- 첨부파일 분석 결과가 부모 메일과 연결된다.
- 날짜, 수량, PO 번호 등 핵심 값이 근거 위치와 함께 저장된다.
- 핵심 첨부 분석 실패 시 후속 단계가 자동 확정하지 않는다.

## M3 통합 사실·요약·분류

### 주요 작업

- `MailFacts`와 `EvidenceItem` 계약 구현
- 본문과 첨부의 사실 통합 및 충돌 감지
- 업무 수행용 구조화 요약 생성
- 상위 업무 영역과 세부 업무 유형 분류
- 요청 행동, 기한, 누락 정보, 긴급 신호 생성

### 완료 조건

- 요약과 분류가 동일한 사실과 근거를 참조한다.
- 근거 없는 식별자·날짜·수량은 성공 결과로 저장되지 않는다.
- 본문과 첨부가 충돌하면 사람 검토 신호가 생성된다.

## M4 조직·합성 데이터 기반

### 주요 작업

- 합성 담당자 8명과 역량 데이터 구성
- 고객 12개, 제품군 6개, 선박·프로젝트 15개 구성
- 고객·제품·프로젝트·업무 유형별 라우팅 규칙 40개 구성
- 수신 메일 200건과 첨부파일 120개 구성
- 정답 담당자와 근거가 있는 평가 사례 100건 구성

### 완료 조건

- 신규 고객, 후보 동점, 비활성 담당자, 본문/첨부 충돌, 긴급 오탐, 첨부 실패가 포함된다.
- 합성 데이터의 출처, 생성 방식, 기대값, 실제 데이터와의 차이가 기록된다.
- 담당자 배정 기능을 실제 조직 데이터 없이도 반복 평가할 수 있다.

## M5 Agentic Retrieval

### 주요 작업

- 고객·도메인·제품·프로젝트 정확 검색
- 라우팅 규칙 검색
- Qdrant 과거 메일·첨부·확정 배정 검색
- reranker와 context builder 구현
- Retrieval Planner와 Context Evaluator 구현
- 최대 3회의 검색 반복과 trace 저장

### 완료 조건

- 검색 결과가 PostgreSQL 원본으로 역추적된다.
- 낮은 관련성 결과는 최종 문맥에서 제외된다.
- 정보가 부족하면 질의를 바꾸거나 다른 검색 도구를 선택한다.

## M6 담당자 배정

### 주요 작업

- 조직 저장소에서만 담당자 후보 생성
- 고객, 제품, 업무 유형, 프로젝트, 과거 배정, 유사 사례, 활성 상태 점수 계산
- 예외 규칙 우선 적용
- Validation Agent로 역량·규칙·근거 충돌 검사
- 자동 배정과 사람 검토 정책 적용
- 사용자 확정·재배정·전달·완료 이력 저장

### 완료 조건

- 담당자 Top-1과 Top-3 평가가 가능하다.
- 자동 배정 근거와 후보별 점수가 표시된다.
- 사용자 재배정이 최초 AI 결과를 덮어쓰지 않고 이력으로 남는다.
- 긴급 미할당 메일은 관리자 검토 대상으로 조회된다.

## M7 운영 평가와 안정화

### 주요 작업

- 단계별 품질, 지연 시간, 실패율, 사용자 수정률 기록
- 프롬프트·모델·workflow version 회귀 평가
- stale run 복구, 재시도 제한, dead-letter 상태 구현
- 개인정보와 민감 메일 trace 마스킹
- 운영 데이터 확보 후 합성 평가셋과 분포 차이 분석

### 초기 합격 기준

- 첨부 문서 유형 정확도 90% 이상
- 핵심 필드 평균 F1 85% 이상
- 세부 업무 유형 macro F1 85% 이상
- 담당자 Top-1 정확도 85% 이상
- 담당자 Top-3 recall 95% 이상
- 자동 배정 precision 95% 이상
- 긴급 메일 오배정률 2% 이하
- 근거 없는 생성 사실 비율 1% 이하

## M8 부가 기능

1차 담당자 배정 흐름이 안정화된 뒤 다음 기능을 추가한다.

- 이메일 답변 초안
- 자동 견적 폼
- 고객 요청별 후속 조치 제안
- 반복 문의·발주 패턴 분석
- 담당자별 업무량과 지연 분석

부가 기능도 원본 근거, 사람 검토, 사용자 수정, 평가 기록을 남겨야 한다.
